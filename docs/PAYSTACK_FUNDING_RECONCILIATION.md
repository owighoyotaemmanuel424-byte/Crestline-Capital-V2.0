# Paystack Funding Reconciliation

Crestline Capital must create a server-owned pending `transactions` record before a customer is sent to Paystack. The transaction reference is generated by Crestline and is the only reference accepted by webhook reconciliation.

## Funding intent

The authenticated application layer should call the Convex `funding.createIntent` mutation with a valid idempotency key and requested amount. That mutation derives the customer's primary account and currency from the authenticated identity; clients must not choose another user's account or currency.

The Paystack initialization request must then use the returned Crestline reference and server-derived amount/currency. The Paystack secret key must remain server-side.

## Webhook rules

1. Verify `x-paystack-signature` against the exact raw request body using HMAC-SHA512.
2. Deduplicate by provider event ID.
3. Process only `charge.success` events whose provider status is `success`.
4. Match the event reference to the server-created pending transaction.
5. Verify amount (Paystack minor units vs transaction major units) and currency.
6. Reject unmatched, malformed, or mismatched payments without crediting a balance.
7. Post exactly one credit ledger entry and update the transaction to `SUCCESS`.
8. Mark the webhook event `PROCESSED` only after the ledger credit succeeds.

No webhook path should trust a client-supplied account, user ID, email, or amount to determine where funds are credited.
